# v0.2 设计文档 — 外部验证 + 基础沙箱

> 版本目标：解决 LLM 自评估不可靠问题 + 实现文件级隔离

---

## 一、背景与问题

### 1.1 当前问题

**LLM 自评估不可靠**：
- LLM 常在"差不多"时就停止，而非真正完成任务
- 无法保证任务完全达成预期目标
- 缺乏外部可验证的完成标准

**安全隔离不足**：
- 当前 Pace 直接操作源文件
- Agent 被劫持可能修改/删除重要文件
- 无法审查变更后再合并

### 1.2 设计来源

基于以下学习成果：

1. **Ralph Loop** — 外部验证机制（verifyCompletion）
2. **Claude Code Sandbox** — 工作区隔离
3. **NVIDIA AI Red Team** — 安全最佳实践
4. **pi-mono** — Compaction 结构化摘要

## 二、核心设计

### 2.1 TaskCompletion — 外部验证机制

**接口定义**：

```typescript
/**
 * 任务完成验证器
 * 
 * 用于外部验证任务是否真正完成，解决 LLM 自评估不可靠的问题
 */
interface TaskCompletion {
  /**
   * 验证任务是否完成
   * @returns complete: 是否完成, reason: 原因说明
   */
  verifyCompletion(): Promise<{ complete: boolean; reason: string }>;

  /**
   * 最大迭代次数（可选）
   * 达到后强制停止
   */
  maxIterations?: number;

  /**
   * 最大 token 消耗（可选）
   * 达到后强制停止
   */
  maxTokens?: number;

  /**
   * 最大成本（可选，单位：美元）
   * 达到后强制停止
   */
  maxCost?: number;
}
```

**与 TerminationController 集成**：

```typescript
interface TerminationController {
  // 现有的停机触发器
  triggers: {
    budget: BudgetStop;
    retry: RetryStop;
    // 新增：外部验证触发器
    completion: CompletionStop;
  };

  // 检查是否应该停机
  shouldStop(): Promise<{ stop: boolean; reason: string }>;
}

interface CompletionStop {
  type: 'completion';
  taskCompletion: TaskCompletion;
  // 每隔 N 个 turn 检查一次
  checkInterval: number;  // default: 1
}
```

**使用示例**：

```typescript
const agent = new Pace({
  // ... 其他配置

  taskCompletion: {
    verifyCompletion: async () => {
      // 示例：验证测试迁移是否完成
      const vitestExists = await fileExists('vitest.config.ts');
      const jestNotExists = !(await fileExists('jest.config.js'));
      const noJestImports = !(await grepExists('**/*.test.ts', '@jest'));
      
      if (vitestExists && jestNotExists && noJestImports) {
        return { complete: true, reason: 'Migration complete' };
      }
      
      return { 
        complete: false, 
        reason: 'Structural checks failed: vitest.config.ts missing or jest references remain' 
      };
    },
    maxIterations: 50,
    maxTokens: 100_000,
  },
});
```

### 2.2 SandboxManager — 工作区隔离

**接口定义**：

```typescript
/**
 * 沙箱配置
 */
interface SandboxConfig {
  /** 工作区根目录（隔离区域） */
  workspaceRoot: string;
  
  /** 源文件根目录（原始位置） */
  sourceRoot: string;
  
  /** 禁止访问的路径模式（优先级最高） */
  deniedPaths: string[];  // 如: ['~/.ssh/**', '~/.aws/**', '**/.env']
  
  /** 允许访问的额外路径（只读） */
  readOnlyPaths?: string[];
  
  /** 网络隔离模式 */
  networkMode: 'isolated' | 'allow' | 'proxy';
  
  /** 允许的域名列表（networkMode = 'allow' 时生效） */
  allowedDomains?: string[];  // 如: ['api.anthropic.com', 'api.openai.com']
  
  /** 资源限制 */
  limits?: {
    maxFileSize?: number;    // 单文件大小上限（字节）
    maxTotalSize?: number;   // 工作区总大小上限
    timeoutMs?: number;      // 操作超时
  };
}

/**
 * 文件变更记录
 */
interface FileChange {
  /** 文件路径（相对于 sourceRoot） */
  path: string;
  
  /** 变更类型 */
  type: 'created' | 'modified' | 'deleted';
  
  /** unified diff（modified 时） */
  diff?: string;
  
  /** 风险评估 */
  risk: 'low' | 'medium' | 'high' | 'critical';
  
  /** 冲突信息（如果源文件也变了） */
  conflict?: {
    sourceModified: boolean;
    conflictType: 'content' | 'deleted' | 'created';
  };
}

/**
 * 沙箱管理器
 */
interface SandboxManager {
  /**
   * 初始化工作区
   * 创建隔离目录，准备同步文件
   */
  initialize(): Promise<void>;

  /**
   * 同步文件到工作区（源 → 工作区）
   * @param sourcePath 相对于 sourceRoot 的路径
   * @returns 工作区内的绝对路径
   */
  syncToWorkspace(sourcePath: string): Promise<string>;

  /**
   * 批量同步文件
   */
  syncBatch(paths: string[]): Promise<string[]>;

  /**
   * 获取所有变更（工作区 vs 源）
   */
  getChanges(): Promise<FileChange[]>;

  /**
   * 检查特定文件的变更
   */
  getFileChange(path: string): Promise<FileChange | null>;

  /**
   * 合并变更回源（需要用户确认）
   */
  mergeToSource(changes: FileChange[], options?: MergeOptions): Promise<MergeResult>;

  /**
   * 丢弃工作区所有变更
   */
  discard(): Promise<void>;

  /**
   * 销毁工作区
   */
  destroy(): Promise<void>;

  /**
   * 检查路径是否在沙箱内
   */
  isSandboxed(path: string): boolean;

  /**
   * 重写路径（源路径 → 工作区路径）
   */
  rewritePath(sourcePath: string): string;

  /**
   * 事件：文件变更时触发
   */
  onFileChange: Event<FileChange>;
}

interface MergeOptions {
  /** 是否跳过冲突检查 */
  skipConflictCheck?: boolean;
  /** 冲突解决策略 */
  conflictStrategy?: 'abort' | 'overwrite' | 'merge';
}

interface MergeResult {
  success: boolean;
  mergedFiles: string[];
  skippedFiles: string[];
  conflicts: FileChange[];
  error?: string;
}
```

**工作流程**：

```
用户请求: "修改 src/auth.ts"

┌─────────────────────────────────────────────────────────┐
│  1. SandboxManager.syncToWorkspace('src/auth.ts')       │
│     → cp src/auth.ts → .pace/workspace/src/auth.ts      │
└─────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│  2. Agent 在工作区操作                                   │
│     → edit('.pace/workspace/src/auth.ts', ...)          │
└─────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│  3. 任务完成，触发 SandboxManager.getChanges()           │
│     → 生成 FileChange[] (diff + risk)                   │
└─────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│  4. MergeManager 审批流                                  │
│     → 显示 diff 报告                                    │
│     → 用户确认 [Approve / Reject / View Full Diff]      │
└─────────────────────────────────────────────────────────┘
                           │
               ┌───────────┴───────────┐
               ▼                       ▼
┌──────────────────────┐   ┌──────────────────────┐
│ 5a. Approve          │   │ 5b. Reject           │
│ → mergeToSource()    │   │ → discard()          │
│ → 变更合并到源文件    │   │ → 工作区变更被丢弃    │
└──────────────────────┘   └──────────────────────┘
```

### 2.3 MergeManager — 审批流

**接口定义**：

```typescript
/**
 * 合并管理器
 */
interface MergeManager {
  /**
   * 生成变更报告
   */
  generateReport(changes: FileChange[]): Promise<ChangeReport>;

  /**
   * 评估变更风险
   */
  assessRisk(change: FileChange): 'low' | 'medium' | 'high' | 'critical';

  /**
   * 检测冲突（工作区变更 vs 源文件变更）
   */
  detectConflicts(changes: FileChange[]): Promise<FileChange[]>;

  /**
   * 请求用户审批（CLI 交互）
   */
  requestApproval(report: ChangeReport): Promise<ApprovalDecision>;

  /**
   * 执行合并
   */
  executeMerge(changes: FileChange[], decision: ApprovalDecision): Promise<MergeResult>;
}

interface ChangeReport {
  /** 变更总数 */
  totalChanges: number;
  
  /** 按风险等级分组 */
  byRisk: {
    low: FileChange[];
    medium: FileChange[];
    high: FileChange[];
    critical: FileChange[];
  };
  
  /** 冲突文件 */
  conflicts: FileChange[];
  
  /** 摘要文本（用于 CLI 显示） */
  summary: string;
  
  /** 详细 diff（用于逐文件审查） */
  detailedDiffs: Map<string, string>;
}

type ApprovalDecision = 
  | { type: 'approve-all' }
  | { type: 'approve-selected'; files: string[] }
  | { type: 'reject-all' }
  | { type: 'review-file'; file: string };
```

### 2.4 Guardrails — 从失败中学习

**接口定义**：

```typescript
/**
 * Guardrail 规则
 */
interface GuardrailRule {
  /** 规则 ID */
  id: string;
  
  /** 规则描述 */
  description: string;
  
  /** 触发条件 */
  trigger: {
    errorPattern?: RegExp;       // 错误消息匹配
    toolName?: string;           // 特定工具
    failureCount?: number;       // 连续失败次数
  };
  
  /** 建议的操作 */
  suggestion: string;
  
  /** 创建时间 */
  createdAt: number;
  
  /** 命中次数 */
  hitCount: number;
}

/**
 * Guardrails 管理器
 */
interface GuardrailsManager {
  /**
   * 从失败中学习新规则
   */
  learnFromFailure(failure: FailureContext): Promise<GuardrailRule>;

  /**
   * 获取所有规则
   */
  getRules(): Promise<GuardrailRule[]>;

  /**
   * 检查是否应该触发规则
   */
  checkTrigger(context: ExecutionContext): Promise<GuardrailRule | null>;

  /**
   * 应用规则建议
   */
  applySuggestion(rule: GuardrailRule): Promise<void>;
}

interface FailureContext {
  /** 失败的工具 */
  tool?: string;
  
  /** 错误消息 */
  error: string;
  
  /** 失败时的上下文 */
  context: string;
  
  /** 用户反馈（如果有） */
  userFeedback?: string;
}
```

**存储位置**：

```
.pace/
├── guardrails/
│   └── rules.json       # Guardrail 规则库
└── workspace/           # 沙箱工作区
```

## 五、验收标准

### 5.1 功能验收

| # | 验收项 | 验证方式 |
|---|--------|----------|
| F1 | `verifyCompletion` 返回 true 时 Agent 正确停止 | 构造完成条件测试 |
| F2 | `maxIterations` 限制生效 | 设置低阈值触发 |
| F3 | 文件同步到工作区，源文件不变 | 修改后检查源文件 |
| F4 | `getChanges` 正确返回所有变更 | 对比 git diff |
| F5 | 审批流正确显示 diff 并接受用户选择 | 手动测试 |
| F6 | 合并后源文件正确更新 | 对比 diff |
| F7 | Guardrails 能从失败中学习规则 | 构造重复失败场景 |

### 5.2 性能验收

| 指标 | 目标 |
|------|------|
| 文件同步延迟（100 文件） | < 500ms |
| Diff 计算延迟 | < 100ms / 文件 |
| `verifyCompletion` 调用延迟 | < 50ms（不含用户逻辑） |

### 5.3 安全验收

| 指标 | 目标 |
|------|------|
| 源文件在合并前不被修改 | 100% |
| deniedPaths 生效 | 100% |
| 审批流不可绕过 | 100% |

## 六、风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 大文件同步性能差 | 用户体验下降 | 增量同步 + 文件大小限制 |
| 冲突检测复杂 | 合并失败 | 提供多种冲突解决策略 |
| `verifyCompletion` 实现复杂 | 用户负担重 | 提供常用模板 + 文档 |
